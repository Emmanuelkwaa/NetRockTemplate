# Deployment

<!-- @init:if deploy=aspire -->
Production runs on Docker Compose generated by Aspire. The AppHost (`src/backend/NetRockTemplate.AppHost/Program.cs`) is the single source of truth for development and production.

## Publish or deploy

```bash
# Write docker-compose.yaml and .env into ./aspire-output (images are not built)
aspire publish --project src/backend/NetRockTemplate.AppHost/NetRockTemplate.AppHost.csproj -o aspire-output

# Build the images and run the stack on the current Docker host
aspire deploy --project src/backend/NetRockTemplate.AppHost/NetRockTemplate.AppHost.csproj -o aspire-output
```

`aspire-output/` is git-ignored because its `.env` holds secrets. `aspire deploy` needs a value for every parameter. Pass them as environment variables (names contain dashes, so use `env`) or answer the prompts:

```bash
env "Parameters__jwt-secret=..." "Parameters__public-url=https://app.example.com" \
    aspire deploy --project src/backend/NetRockTemplate.AppHost/NetRockTemplate.AppHost.csproj
```

Production runs on the single-instance `docker-compose.yaml` in the repository root. Aspire is used for local development only.

## First deployment

```bash
cp .env.example .env     # git-ignored; fill in every value
docker compose up -d --build
docker compose ps        # wait until api is healthy
```

<!-- @init:if frontend=svelte -->
The frontend listens on `HTTP_PORT` (default 3000) and proxies `/api/*` to the API on the internal network. The API is not published on the host.
<!-- @init:end -->
<!-- @init:if frontend=blazor -->
The Blazor app listens on `HTTP_PORT` (default 3000) and calls the API on the internal network (`services__api__http__0: http://api:8080`). The API is also published on `API_PORT` (default 8080), because browsers and other clients reach it directly; there is no proxy in front of it. The Blazor image is built from `src/frontend/NetRockTemplate.UI/Dockerfile` with `./src` as the build context.
<!-- @init:end -->
<!-- @init:if frontend=none -->
The API listens on `HTTP_PORT` (default 8080).
<!-- @init:end -->

Put a TLS-terminating reverse proxy in front. To join an existing proxy network such as Coolify, uncomment the `coolify` network block and the `- coolify` lines in `docker-compose.yaml`, and remove the `ports` mapping. For a quick test over plain HTTP without a proxy, set `Hosting__ForceHttps=false`.

## Configuration

Every setting is an environment variable in `.env`, listed with comments in `.env.example`. File storage is always an external S3-compatible service (`FileStorage__*`); the stack does not run MinIO.
<!-- @init:end -->

## Database migrations

The API applies EF Core migrations on startup in Development, and anywhere `Database__MigrateOnStartup=true`.

<!-- @init:if database=managed -->
Managed PostgreSQL runs in the stack with `Database__MigrateOnStartup=true`, so a fresh database is migrated on first start.
<!-- @init:else -->
Against an external database migrations do not run automatically (`Database__MigrateOnStartup=false`). Choose one:

- Apply them from a machine that can reach the database:
  ```bash
  dotnet ef database update --project src/backend/NetRockTemplate.Infrastructure --startup-project src/backend/NetRockTemplate.WebApi --connection "Host=...;Database=...;Username=...;Password=..."
  ```
- Generate an idempotent script for a DBA: `dotnet ef migrations script --idempotent -o migrate.sql` (same project arguments).
- Or set `Database__MigrateOnStartup=true` if the app's database user may change the schema.

### pg_trgm

Fuzzy search uses the `pg_trgm` extension, and the initial migration runs `CREATE EXTENSION IF NOT EXISTS pg_trgm`. On PostgreSQL 13 and later that needs the `CREATE` privilege on the database (pg_trgm is a trusted extension); older versions need a superuser. If the app's user lacks it, ask an administrator to run this once before migrating:

```sql
CREATE EXTENSION IF NOT EXISTS pg_trgm;
```

Background jobs (Hangfire) store their state in the same database, in the `hangfire` schema, which they create on first start.
<!-- @init:end -->

## Health checks

- `GET /health/live` - the process is up (used by the container healthcheck)
- `GET /health/ready` - dependencies are reachable
- `GET /health` - full report
